# Telemetry ingestion (Slice 7.7)

Platform-owned privacy-first telemetry endpoint for anonymous technical product
usage and operational events.

## Endpoint

`POST /api/v1/telemetry`

Route identity: `telemetry.ingest`

Registered only through `RouteRegistry.foundation_v1()` — not ad-hoc in
`create_community_cloud_app()` outside the registry composition pattern.

Production Community Cloud routes after this slice:

- `GET /api/v1/health`
- `POST /api/v1/telemetry`

Single-event ingestion only. No `/events`, `/track`, `/usage`, or
`/telemetry/batch` aliases.

## Schema and policy versions

| Constant | Value | Role |
| --- | --- | --- |
| Community Cloud API contract | `1.0` | Unchanged |
| Request-validation policy | `1.0` | Unchanged |
| Payload-limit policy | `payload-limit-policy:1.0` | Unchanged |
| Logging policy | `community-logging-policy:1.0` | Additive telemetry events under 1.0 |
| Event-identity policy | `community-event-identity-policy:1.0` | Unchanged |
| **Telemetry schema** | `1.0` | Envelope schema for this endpoint |
| **Telemetry policy** | `community-telemetry-policy:1.0` | Privacy / allowlists |

Only telemetry schema version `1.0` is accepted. Unsupported versions return a
canonical validation error (`unsupported_telemetry_schema`).

## Privacy statement

The telemetry endpoint accepts only bounded anonymous technical events. It does
not accept source code, repository contents, file paths, command arguments,
prompts, credentials, personal information, or unrestricted metadata.

Rejected values are never echoed in error responses or logs.

## Request envelope

```json
{
  "schema_version": "1.0",
  "event_id": "client-stable-id-01",
  "event_type": "application_started",
  "client": {
    "name": "codestrata_cli",
    "version": "0.2.0",
    "platform": "darwin"
  },
  "installation_id": "optional-anonymous-id",
  "occurred_at": "2026-07-29T18:00:00Z",
  "properties": {
    "feature": "assess",
    "operation": "run",
    "outcome": "succeeded",
    "duration_bucket": "1s_to_5s",
    "count": 1,
    "flags": ["local"]
  }
}
```

Unknown fields are rejected. Top-level body must be a JSON object (not an array).

### Required

- `schema_version` — exact `1.0`
- `event_id` — client-supplied `ApiEventId` (stable across retries)
- `event_type` — allowlisted generic name
- `client` — bounded descriptor

### Optional

- `installation_id` — anonymous `ApiInstallationId`; never generated by the server
- `occurred_at` — RFC3339 / ISO-8601 string; metadata only; not part of event-key
  identity; **does** participate in payload fingerprint when present
- `properties` — bounded allowlisted fields only

## Client names

- `codestrata_cli`
- `vscode_extension`
- `other_extension`

Client `name` participates in event identity as `client_type`. Version and
platform are payload facts only.

## Event types

- `application_started`
- `application_completed`
- `feature_invoked`
- `feature_completed`
- `operation_failed`

No assessment metadata, CLI-command, extension-interaction, or AI-usage events
in this slice (later Epic 7 slices own those).

## Properties

Allowlisted optional fields: `feature`, `operation`, `outcome`,
`duration_bucket`, `count`, `flags`.

- `outcome`: `succeeded` | `failed` | `cancelled` | `unavailable`
- `duration_bucket`: `under_1s` | `1s_to_5s` | `5s_to_30s` | `30s_to_2m` |
  `over_2m` | `unavailable`
- `count`: non-negative integer ≤ 10000
- `flags`: small list of safe labels

No raw millisecond durations, nested arbitrary objects, paths, URLs, exception
text, or free-form metadata.

## Request ID versus event ID

| Identifier | Role |
| --- | --- |
| `X-Request-Id` / transport request id | Per HTTP attempt; logging/correlation only |
| `event_id` | Client logical event identity; required; stable across retries |

They must not be conflated.

## Event identity and retries

For every valid request the service:

1. Builds `EventIdentityScope` from API version, client name, optional
   installation id, event type, and `event_id`
2. Builds deterministic `event_key`
3. Builds `payload_fingerprint` from the validated envelope
4. Classifies retry state via authoritative `EventIdentityLookup` when configured

### Fingerprint decision

`event_id` remains in fingerprint material because the event-identity policy
forbids excluding identity fields. `event_key` still owns scoped logical
identity. Transport `request_id` is never part of the telemetry model and is
excluded by the fingerprint exclusion list when present on other payloads.

### Retry outcomes

| Classification | HTTP | Body status | Sink | Identity record |
| --- | --- | --- | --- | --- |
| First seen + sink accepted | **202** | `accepted` | called once | after sink acceptance |
| Exact retry | **200** | `already_accepted` | not called | not re-recorded |
| Conflicting retry | **409** | `event_identity_conflict` | not called | not recorded |
| Lookup/recorder missing | **503** | `event_identity_unavailable` | not called | — |
| Sink unavailable | **503** | `telemetry_sink_unavailable` | — | not recorded |

Fail closed: without an authoritative lookup **and** recorder, the endpoint
does not claim `first_seen` and does not accept events.

Retry-safe identity reduces duplicate logical events only when an authoritative
identity store and accepting telemetry sink are configured. It is not an
exactly-once delivery guarantee.

### Atomicity limitation

Without a transactional production store, sink acceptance and identity recording
cannot be atomic. Identity is recorded only after sink acceptance. Recorder
failure after acceptance returns `event_identity_record_failed` (503). Behavior
is retry-safe best effort pending durable infrastructure.

## Responses

```json
{
  "retry_status": "first_seen",
  "safe_event_reference": "evt-...",
  "schema_version": "1.0",
  "status": "accepted"
}
```

Never includes: `event_key`, `payload_fingerprint`, raw `event_id`,
`installation_id`, server timestamp, storage location, or internal record IDs.

## Ports (no production persistence)

Injectable on `create_community_cloud_app()`:

- `telemetry_sink` — default `UnavailableTelemetryEventSink` (503, never
  “accepted while discarded”)
- `event_identity_lookup` / `event_identity_recorder` — default unset (fail closed)

Tests may use `InMemoryTelemetryEventSink` and `InMemoryEventIdentityStore`.

No database, object storage, files, Redis, Kafka, queues, or data lake in this
slice.

## Logging

Additive safe events under `community-logging-policy:1.0`:

- `telemetry_received`
- `telemetry_accepted`
- `telemetry_retry`
- `telemetry_conflict`
- `telemetry_rejected`

Allowed fields include `safe_event_reference`, `source_event_type`,
`retry_status`, `telemetry_schema_version`, `telemetry_policy_version`, status
code, and route id. Never logs payloads, raw event IDs, installation IDs,
fingerprints, or event keys. Logging failures never affect endpoint behavior.

## Authentication and rate limiting

This endpoint is unauthenticated in Slice 7.7 (authentication is Slice 7.13).

Unauthenticated does not mean trusted: strict privacy and schema controls apply.
Production deployment should not be treated as complete before auth and rate
limiting slices. No temporary API keys. No IP-derived identity. No rate-limit
headers (Slice 7.12).

## Boundaries

Out of scope here:

- Assessment metadata ingestion (7.8)
- CLI-specific rich events (7.9)
- Extension-specific events (7.10)
- AI usage events (7.11)
- Rate limiting (7.12)
- Authentication (7.13)
- Community Data Lake / durable stores / workers / serverless deployment

Health remains independent of telemetry sink and identity stores.
