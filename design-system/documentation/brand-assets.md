# Brand assets

**Policy:** `codestrata-brand-asset-policy:1.0`
**Contracts:** `design-system/contracts/assets.json`, `design-system/contracts/icons.json`
**Slice:** 14.10 (additive under Design System 1.0)

## Asset authority

The Design System is the product visual authority. `design-system/assets/brand/`
holds the master mark, the master wordmark, and every approved variant. Product
surfaces consume approved derivatives; they never define their own geometry or
colour.

`governance/assets/` is a **historical archive**. It holds the originally
authored strata geometry and outlined wordmark in the amber-era palette, and it
is explicitly non-authoritative for product colour. There is exactly one master.

Colour comes from `design-system/tokens/catalog.json`, which is captured from the
live website. No asset introduces a colour outside that palette.

## Master mark

`codestrata-mark.svg` — four strata bars on a 22-unit grid, alternating inset,
1.2-unit corner radius. Bars run top to bottom in the token order `muted`,
`teal_dark`, `teal`, `rust`. The mark is teal-first with rust used once, matching
the website's visual language.

Everything else is generated from that geometry by
`scripts/generate_brand_assets.py`, which reads the token catalog, writes the
master set and each consumer copy, and supports `--check` for drift detection.

## Wordmark decision

The wordmark is a **dedicated outlined vector asset** (`codestrata-wordmark.svg`)
used only in site and portal lockups, where a font-independent image is required.
Product surfaces — reports, the extension, the Marketplace listing — render
"CodeStrata" as typography rather than as an image. Both routes are authoritative;
neither depends on an installed font, because the asset carries outlines.

## Background usage

Full-colour assets are for `canvas`, `paper`, and `paper_soft`. On dark
backgrounds CodeStrata is monochrome light (`night_ink`, optionally on a `night`
plate); the teal/rust palette is light-first, so no full-colour dark variant was
created. Host-tinted surfaces use the `currentColor` derivatives.

## Clear space and minimum size

Clear space: keep at least one strata bar height of empty space on every side of
the mark or lockup. That is enough to prevent crowding without a corporate
measurement system.

Minimum sizes: lockup no smaller than 120px wide; wordmark no smaller than 96px
wide; mark no smaller than 16px. Below 24px use the simplified monochrome mark.

## Surface derivatives

**Documentation site.** VitePress references `/brand/lockup-horizontal-on-light.svg`,
`/brand/lockup-horizontal-on-dark.svg`, and `/favicon.svg` from `docs/public/`.
The documentation repository is exported independently, so those files are
byte-identical copies of the masters rather than monorepo-relative references.
The generator writes both sides, and verification compares checksums.

**Platform API documentation portal.** The Swagger surface serves its own static
`brand/` directory and follows the same copy rule.

**Assessment report.** The report packages `codestrata-mark-mono.svg` with the
Engine distribution and inlines it into the self-contained HTML. It replaced an
amber-era 140×40 raster that was base64-embedded into every report. The product
identity block is now the vector mark plus the product name as text.

**Intelligence report.** The commercial Platform must not import Engine
presentation modules, so the same markup is embedded as the `BRAND_MARK_SVG`
constant in its renderer. Same authority, different implementation; verification
asserts the markup is identical.

**VS Code.** The activity icon is a simplified three-bar `currentColor`
derivative: monochrome, theme-safe, legible at 16–24px, no wordmark, no raster.
Generic commands continue to use codicons.

**Marketplace.** The 128×128 package icon is a raster derivative whose bars are
projected from the master geometry, generated by
`vscode-plugin/scripts/generate_marketplace_visuals.py`. The gallery itself
remains owned by Slice 14.6.

## Favicon

One SVG favicon derived from the master, served at `/favicon.svg`. No PNG
fallbacks and no ICO, because no consumer requires them. Add sizes only with a
named consumer.

## Icon language

CodeStrata owns product identity, not a generic UI icon library. Severity, risk,
and status meaning stays with `codestrata-visualization-contract:1.0`; generic
actions use host-native icons; arrows are Unicode. Icons never carry meaning by
colour alone, and decorative marks are `aria-hidden` where a text label already
names the surface.

## Legacy asset policy

The amber-era identity (`#d98a3d`, `#4fb3a5`, and the related neutrals) must not
appear in any active product surface. It remains in `governance/assets/` as
history and is never referenced by a shipping surface. AIMF and Cursor have no
visual assets in the repository; textual history and schema compatibility
references are untouched, since this slice covers visual assets only.

## Boundaries

Accessibility acceptance is owned by Slice 14.11
(`codestrata-accessibility-responsive-policy:1.0`) and is not claimed here.
Deployment configuration belongs to Slice 14.12; asset paths remain static and
site-root relative so that boundary stays clean. Report information architecture
(14.9) and visualization semantics (14.8) are unchanged.
