# Customer Demo Checklist

**Status:** Foundation  
**Authority:** Playbook

## Objective

Run a consistent, trustworthy CodeStrata demo without surprising architecture or
branding mistakes.

## Scope

Live demos for customers or design partners.

## Before the demo

- [ ] Deterministic `--no-ai` path rehearsed (always have a fallback)
- [ ] Sample repo sanitized (no secrets)
- [ ] Report HTML opens cleanly offline
- [ ] Branding uses **CodeStrata** / Engine / Platform correctly
      ([BRANDING_GUIDELINES.md](../standards/BRANDING_GUIDELINES.md);
      visuals per [`../assets/DESIGN-SYSTEM.md`](../assets/DESIGN-SYSTEM.md))
- [ ] Know which capabilities are Community vs Platform

## Demo flow (suggested)

1. Problem framing (modernization assessment, evidence-first)
2. `assess` on sample repository (deterministic)
3. Walk Findings → Recommendations → Evidence
4. Optional: AI advisor narrative (label as interpretation)
5. Optional: Platform portfolio / executive views if in scope

## Messaging guardrails

1. Deterministic analysis first; AI second.
2. Do not claim source retention or tenancy properties you cannot show.
3. Do not demo unreleased architecture redesigns as shipped.

## After the demo

- [ ] Capture questions and friction
- [ ] File follow-ups; do not promise unplanned features
